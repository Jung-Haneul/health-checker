# 증상 상담 (첫 구현)

앱 전체 전제는 [PRODUCT.md](../../../PRODUCT.md)를 따릅니다. 이 스펙은 그중 첫 구현 범위만 다룹니다.

## 사용자에게 보이는 결과

사용자는 한 화면에서 몸의 증상을 자유롭게 말합니다(예: "옆머리가 아프고 윗배가 더부룩해요"). 서비스는 원인 후보가 여럿이면 질문을 던지고, 사용자의 답으로 원인을 하나로 좁힙니다. 그런 다음 의심되는 원인, 대처법, 약국에서 살 수 있는 약을 알려줍니다. 증상이 심각해 보이면 원인과 함께 가야 할 진료과를 바로 제안합니다.

## 범위

- 증상 입력과 대화 화면 하나. 로그인과 대화 기록 저장은 없습니다.
- 원인 후보가 여럿일 때 서비스가 질문하고 사용자가 답하는 좁히기 과정.
- 원인이 특정되면 "OO이 의심됩니다" 형태의 결과, 대처법, 약 안내.
- 심각해 보이는 증상에 대한 즉시 안내(원인과 진료과 제안).
- 증상 입력 화면의 상시 고지.

## 인수 기준

1. 증상을 한 문장으로 입력하고 보내면, 서비스가 질문 또는 결과로 답한다.
2. 입력한 증상으로 원인 후보가 여럿이면 질문이 나온다. 사용자가 답할 때마다 다음 질문이나 결과가 이어지며, 질문은 한 번에 하나씩 나온다.
3. 결과에는 "의심됩니다" 수준의 표현으로 원인이 하나 나오고, 대처법(예: 이온음료 마시기)과 "낫지 않으면 병원에 가세요" 안내가 함께 나온다. 확정 진단 표현은 쓰지 않는다.
4. 원인이 특정되면 약국에서 살 수 있는 약이 제품명, 효능, 사용법, 주의사항과 함께 나온다. 이 내용은 식약처 e약은요 API 응답에서 가져온 것이다.
5. e약은요에서 해당 약을 찾지 못하면 약 목록을 비우고 "약국에서 상담하세요"를 보여준다. 약 이름을 지어내서 보여주지 않는다.
6. 심각해 보이는 증상(예: 가슴 통증과 호흡곤란)을 입력하면, 질문 없이 의심 원인과 가야 할 진료과(예: 응급의학과)가 바로 나온다.
7. 증상 입력 화면에는 항상 두 가지 고지가 보인다. 하나는 "입력한 내용이 구글의 서비스 개선에 쓰일 수 있으니 이름·연락처 같은 개인정보는 적지 마세요"이다. 다른 하나는 "의사가 아니며 확정 진단이 아닙니다"이다. 스크롤하거나 대화가 길어져도 가려지지 않는다.
8. API 호출이 실패하면 오류 상태를 보여주고 다시 시도할 수 있다. 대화 내용은 유지된다.
9. 모바일 폭(약 400px)에서도 입력, 질문, 결과, 고지가 모두 보인다.

## 확정된 제약과 근거

- 증상 해석과 질문, 원인·대처법 생성은 Gemini 무료 티어를, 약 정보는 e약은요를 쓴다. 키는 서버에서만 다룬다. 근거는 [ai-and-data-sources](../../decisions/ai-and-data-sources.md)에 있다.
- UI는 shadcn 기반 구성과 공통 shell을 따른다. 세부 규칙은 [ui-composition](../../decisions/ui-composition.md)에 있다.
- 약은 약국에서 살 수 있는 약까지만, 원인은 "의심" 수준으로만 말한다([PRODUCT.md](../../../PRODUCT.md)의 경계).

## 가정 (에이전트가 정한 기본값, 바꿀 수 있음)

- 한국어로만 응답한다.
- 사용 모델은 무료 Flash 계열(예: `gemini-2.5-flash`)이며, 구현 시 최신 공식 문서에서 확인한다.
- 질문은 최대 5번까지 이어지고, 그때까지 하나로 좁혀지지 않으면 가장 유력한 원인을 의심으로 안내한다.
- 약 검색은 LLM이 낸 효능 키워드로 e약은요를 조회해 상위 몇 개를 보여준다. 요청 필드 이름은 구현 때 명세로 확인한다.
- 나이, 임신 여부 같은 개인 조건은 묻지 않는다. 대신 e약은요의 주의사항을 약과 함께 보여준다.

## 범위 밖

- 로그인, 대화 기록 저장, 데이터베이스.
- 실제 병원 검색과 위치 안내(진료과 이름 제안까지만).
- 이미지, 음성 입력.
- 보안 하드닝, 호출량 방어 같은 운영용 대비(학습용 템플릿 예산 때문).

## 보류

- "도움이 안 됐다고 느끼는 모습"과 그 측정은 정하지 않았다. 지금은 성공 신호(대처 후 증상 완화)를 앱 안에서 측정하지 않는다.

## 남은 위험

- LLM이 잘못된 원인을 그럴듯하게 제시할 수 있다. 의심 표현, 상시 고지, 병원 안내로만 완화한다.
- 무료 티어의 호출 한도에 걸리면 응답이 실패할 수 있다(인수 기준 8의 오류 상태로 처리).
- e약은요는 일반의약품 중 공급 실적이 있는 제품만 있어, 일부 증상에는 약 목록이 비어 나올 수 있다.
- 무료 티어에 보낸 입력이 구글 제품 개선에 쓰이는 점은 고지로만 대응한다.
